# Pending Tests

The current release needs manual verification in these areas:

- Canvas node management: the bottom toolbar should expose a node list panel (also reachable from the layer popover in a node's hover toolbar) that lists every node in the canvas, filters the list by node type, and supports selecting several rows and renaming them in one action (a single selection keeps the exact name, multiple selections get numbered suffixes). Each row should toggle lock and hide. A locked node cannot be dragged, resized, edited, deleted, or picked up by range selection, but stays selectable so it can be unlocked, and a locked frame must still carry its children when dragged. A hidden node disappears from the canvas and cannot be clicked or targeted by a connection, but stays listed so it can be shown again. A single undo should revert each lock, hide, or rename action.
- Canvas frames: the node toolbar should offer a Frame action that adds a flat, rounded container with its title above the top-left corner and no shadow. Dragging nodes onto the frame should nest them inside it, with the nodes staying visually above the container and the frame highlighting as a drop target while dragging. Dragging the frame should move its nested children with it; deleting the frame should release the children instead of deleting them, and dragging a child out of the frame should release it from the frame.
- Canvas rulers: the canvas area should show a coordinate ruler along its top and left edges, reading in canvas units. The numbers should track panning and zooming, and tick spacing should widen automatically when zoomed out so labels never collide. The rulers are display-only and must not capture clicks or drags.
- Canvas grid snap: dragging nodes should snap to a 16px canvas grid while alignment guides still win - when an edge or centre comes within 6 screen pixels of another node, the guide takes priority over the grid. The grid is measured in canvas units, so the same drag feels consistent at every zoom level. Verify by dragging a node with no neighbours nearby (it should land on 16px multiples) and then dragging it next to another node (it should snap flush to that node's edge instead).
- Alignment and distribution: with two or more nodes selected, the selection toolbar should show six align actions (left, horizontal centres, right, top, vertical centres, bottom) as icon-only buttons with tooltips, plus horizontal and vertical distribution once three or more nodes are selected. Each action should move only the selected nodes to the selection's bounding box (or equalise gaps for distribution), and a single undo should revert the whole move. Verify with 2 selected nodes (no distribute buttons) and with 3+ nodes at different sizes.
- Canvas quick switcher: opening a canvas should show a searchable switcher at the top of the left panel, listing canvases with their node counts, most recently updated first. The current canvas should be highlighted, typing should filter by title, and selecting another canvas should navigate to it without returning to the canvas library.
- Generation execution pipeline: firing many image generations should route every request through one shared queue capped at 2 concurrent requests, so the extra slots stay visible as pending instead of all hitting the provider at once. A failed request should retry up to 3 times with a 2 second backoff before it is reported as failed. Each generation config node should keep only its 5 most recent result versions (older ones are pruned), capture the seed used for the image request in its metadata, and expose a Replay seed action that re-issues the same request with the stored seed so the result is reproducible.
- Generation parameter matrix: a generation config node's panel should show a Matrix chip beside Compose prompt. Opening it should offer Sizes, Counts, and Prompts fields (comma or newline separated), live-preview how many variants will be generated, and provide Clear and Save. Saving a matrix that yields more than one variant should show a count on the chip and relabel the node's Generate button to "Generate N variants"; generating should enqueue every size/count/prompt combination through the same generation queue, while an empty or single-variant matrix keeps plain generation behavior.
- Generation cost dashboard: Settings should include a Cost tab that reads the stored generation cost records and shows the total spend in USD (priced records only), the record count, how many records are unpriced, a by-model breakdown with each model's generation count and summed cost (or an Unpriced label when it has no priced records), and the 20 most recent generations with localised time, model, quantity and unit, plus either their cost or an Unpriced label. An unpriced record must never display as $0.00, Clear should empty the list and reveal the empty state, and the tab must stay inside the existing Settings dialog with no new page or route.
- Smart Canvas layout templates and board layers: the board panel's Auto arrange button should open a dropdown offering Grid (the unchanged default), Single row, Single column, and Feature image (the first image takes the left half of the board at full height while the rest grid into the right half), with every template keeping each image's aspect ratio and integer pixel positions. The same panel should show a Layers popover listing the placed images front-first with a thumbnail, title, eye toggle, and move-forward / move-backward buttons; hidden images should disappear from the board and from the composite, reordering a layer should change both the on-screen stacking order and the composite draw order, and the popover should show an empty state when nothing is placed.
- Nested Smart Canvas boards: dragging a Smart Canvas board onto another board should place it as a board layer instead of a free sibling, and the parent board should render the nested board recursively in place — nested images and nested boards keep back-to-front layer order, hidden layers stay hidden, and the nested board is clipped to its own rectangle inside the parent. Preview composite should flatten nested boards recursively at their rectangle (scaled to the parent's composite size) and still draw plain images as before. Dragging a board should move its whole placed subtree (images and nested boards, recursively, bounded by a visited set), a placed board should show the On board badge and dashed outline like a placed image, and a board must never be droppable into itself or one of its descendants; if stored data already contains such a cycle, rendering and composing must skip the offending node and terminate instead of looping.
- Canvas MCP node tools: an MCP client should see six additional canvas tools on top of the existing ones. `canvas_set_node_flags` sets lock / hide flags on one or more nodes (at least one of `locked` / `hidden` is required), `canvas_bulk_rename` uses the exact title for a single node and numbers multiple nodes as `Title 1`, `Title 2`, … in the given id order, `canvas_align_nodes` aligns the found nodes to their selection bounding box (left / center-x / right / top / center-y / bottom) or equalises gaps (distribute-x / distribute-y, which must produce no position operations with fewer than three known nodes), `canvas_group_nodes` wraps two or more nodes in a group node padded 24px on the sides and 52px on top, records each member's `groupId` and selects the new group, `canvas_ungroup_nodes` clears `groupId` (sent as an explicit `null`, which the browser must delete rather than keep as an empty value) and deletes group nodes that end up without members, and `canvas_duplicate_node` creates a copy offset by 40/40 by default with the same type, title, size and metadata and selects it; unknown ids must be ignored or produce no operations instead of breaking the canvas.
- Canvas agent audit and permissions: Settings should include an Agent tab listing one toggle per agent operation type, all enabled by default so existing agent behavior is unchanged. Turning a type off should block that operation, show a warning, and count it as blocked in the audit log. Every agent operation batch should appear in the audit log with its localised time, operation count, blocked count, and a short summary of its first operations; a replayed entry should be marked as replayed, and replaying it (from the Settings tab while a canvas is open) should re-apply the same operations through the normal canvas path and add a new entry that points back at the original. The log keeps the newest 100 entries, Clear empties it, Restore defaults re-enables every permission, and the whole feature stays inside the existing Settings UI with no new page or route.
- Output node: the bottom toolbar and the connection create menu should offer an Output node that shows one of its direct upstream inputs read-only (image, video, audio, or text) with a source caption, picking the most recently updated upstream input and falling back to the last connection order when timestamps are missing or tied. With two or more Output nodes the earliest created is the default, the default node shows a Default output badge, and every Output node shows a hint naming the default. An Output node has no source handle, never generates, and shows an empty placeholder when nothing is connected.
- Output folder: an Output node should show a compact output-folder row with a folder icon, the bound folder name (or a no-folder-bound label), a bind/change button, and an unbind button. Binding must open the File System Access folder picker asking for read-write access, record the folder name on that node's metadata, survive a page reload (the directory handle is kept in raw IndexedDB under its own `output-folder` key), and warn instead of failing when `showDirectoryPicker` is unavailable. Once bound, every output that lands on that node should be written to the folder automatically, using a file name derived from the source node title (falling back to the source id) with path-illegal characters removed and an extension inferred from the media type (defaulting to png); text outputs are skipped, the same source must never be written twice, writes must happen outside render, and a failed write should only surface in the node row without a toast or a retry loop.
- Local workspace: Settings should include a Workspace tab that binds a local folder via the File System Access API and syncs canvas projects both ways. The tab must warn instead of failing when `showDirectoryPicker` is unavailable, stay inside the existing Settings UI, and never lose a project's data on either choice.
- Image analysis: an image node's hover toolbar should show an Analyze action that opens a dialog with the image's dominant-colour palette as hex swatches, its EXIF key/value list (or an empty note when the image has none), and its perceptual hash, plus a smart-crop section where picking a ratio (1:1 / 4:3 / 3:4 / 16:9 / 9:16) and confirming adds a new cropped image node to the right using content-aware cropping.
- Image OCR: an image node's hover toolbar should show an Extract text action that sends the image to the configured text model and, on success, creates and selects a text node to the right whose title is the first 32 characters of the recognised text (or an OCR result fallback) and whose content is the full text; the tool should be enabled by default in the quick-tools settings and stay consistent after reopening the canvas. With no text model or API key configured it should open the settings dialog instead of calling the API, an empty recognition result should show an error and create no node, and a failed request should surface the error message without leaving a stuck loading toast.
- Image segmentation: an image node's hover toolbar should show a Segment action that opens a point-prompt dialog. Clicking the image adds prompt points (left-click foreground, Alt or right-click background) shown as markers, with undo-last-point and clear-points actions, and the dialog stays responsive on later points because the encoder runs once per image. The first run offers to download the MobileSAM ONNX model (about 45MB, cached in the browser so a second visit is instant) with progress and a clear failure message; running reports the chosen mask's IoU score, tints the mask over the image, shows the cut-out result, and confirming inserts a transparent-background image node to the right of the source. Settings should list it as its own local model that can be downloaded or deleted, and the tool should be enabled by default in the image quick-tools.
